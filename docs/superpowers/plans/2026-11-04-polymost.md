# Polymost, Video Options and Game Speed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the CPU-speed-dependent game speed, then bring duke3d's Polymost renderers (2 software, 3 OpenGL with its 1.1/1.5/2.1 paths, 1 debug) to `d3d` and the editor's 3D mode, with a Video Options page, `duke.cfg` and `build.cfg`.

**Architecture:** duke3d `8f076354eec06b9b41d53419a801b7db93b7685d`'s `source/build/polymost.c`, `polymost_soft.c`, `polymost_opengl.c`, `polymost_opengl_submit.c/.h`, `sdl_opengl.c`, `sdl_opengl_internal.h` are added unchanged first, then adapted. As in duke3d, `polymost.c` is one translation unit that includes the backends (CMake marks the backends `HEADER_FILE_ONLY`); here it is compiled from `draw.c` (which owns the renderer state Polymost reads) by `#include` under `#ifdef POLYMOST`. `draw.c`'s `drawrooms`/`drawmasks`/sprite and 2D entry points branch to Polymost when `rendmode != 0`. The SDL window grows duke3d's GL context path (`sdl_window.c`'s GL parts), kept once made. Video settings live in one new game-side module that the menu and `duke.cfg` share; the editor gets its own small `build.cfg` reader.

**Tech Stack:** C99, SDL2, OpenGL (legacy context, entry points past 1.1 loaded at runtime), CMake/Ninja/MSVC. IDA on `D3D.EXE` for the speed investigation.

**Spec:** `docs/superpowers/specs/2026-11-04-polymost-design.md`

## Global Constraints

- Renderer numbers: 0 classic (default), 1 Polymost solid colour, 2 Polymost software, 3 Polymost OpenGL. The menu lists 0, 2, 3; `/p1` is the only way to 1.
- Command line: `/p<n>` (`/p0`–`/p3`) picks the renderer for one run and is never saved. `/r` stays demo record.
- Classic renderer output must not change in any pixel. Classic demo sync must not change: `MYDEMO_0`–`7` play the same samples.
- Renderers 1–3 may drift slightly from classic's game state; that is a later phase.
- `SETUP.DAT` is read and never written; its layout doesn't change. Its mode byte (`setup_byte(0) == 7`) only affects classic; renderers 2 and 3 take the resolution from `duke.cfg`.
- `LAMEDUKE_OPENGL=OFF` must build and run: renderers 1–3 fall back to 0 and the menu offers Classic only.
- GL entry points past 1.1 are loaded at runtime (`SDL_GL_GetProcAddress`); the binary runs on a 1.1 driver.
- Hor+ for renderers 2 and 3: a resolution wider than 4:3 widens the horizontal FOV and keeps the vertical one, also when looking up/down. The 320x200 2D layout is centred in a 4:3 area; 2D screens with no 3D behind get black side bars. Classic in Fullscreen/Borderless is scaled to fit, 4:3, black bars.
- The 2D (HUD, status bar, menus, text, fills, fades) draws sharp at the full resolution in renderers 2 and 3, and follows filtering in 3.
- Texture filtering: Nearest (default), Bilinear, Trilinear. Mip Level 0–15. Contrast 0.5–1.5 and Saturation 0–2, default 1.0. Supersample Off, 2K, 4K, 8K (1440/2160/4320 tall). VSync On (default)/Off. Display Windowed/Fullscreen/Borderless.
- `duke.cfg` and `build.cfg` sit in the working directory. Missing file = defaults (renderer 0, Nearest, Windowed, 640x480 for renderers 2/3, VSync on, Mip 0, Contrast/Saturation 1.0, Supersample Off). Out-of-range values are clamped; unknown keys are ignored.
- The editor's 2D mode stays 8-bit software at 640x480. The editor writes maps exactly as today.
- Out of scope: hightile/md2/texture cache/OSD/voxels, `GLInternalWidth`/`Height`, a brightness row, screenshot formats, widescreen status-bar art, multiplayer, a GL 2D editor mode.
- Every local change to a file taken from duke3d goes in `source/build/VENDORED.md`, as `build.c`'s are.
- Commits: `subsystem: what it does`, one or two lines, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Build in the MSVC environment: `.superpowers/build.bat` (or `vcvars64.bat` then `cmake --build build`); the plain shell lacks `LIB`. Checks are shell scripts in `.superpowers/checks/`, run from the repo root, printing `<name>: all pass` or `FAIL: ...`.

## Review Focus

1. **The game speed fix under very high frame rates** (vsync off, renderer 3, 1000+ fps): the game must still play at 486 speed, with no stutter from zero-tick frames. Pinned in Task 2 by a check that runs play mode uncapped and compares in-game time against wall time.
2. **Switching renderer mid-level, mid-demo or in the menu**: no crash, no lost palette, HUD still drawn, and switching back to Classic gives Classic's exact frame. Pinned in Task 6 (frame after 0→3→0 equals the classic pin).
3. **A `duke.cfg` from a human**: missing keys, garbage values, CRLF, extra spaces, a resolution of 0x0 or 99999x99999. Defaults or clamps, no crash. Pinned in Task 7's `cfgcheck` cases.
4. **OpenGL unavailable or failing at startup** (`/p3` with no GL, or `LAMEDUKE_OPENGL=OFF`): a message and classic, never a quit. Pinned in Task 5 with a forced-failure env var (duke3d's `gl_forcefail`).
5. **Frame-reading game effects in renderers 2/3** (the `view.c` reactor/plasma loops that need pitch 320, `game.c` screenshots): no out-of-bounds read at 1920x1080. Pinned in Task 6: a renderer-3 run through L1's reactor area and a screenshot at 1920x1080.
